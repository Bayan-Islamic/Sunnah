# Project memory — Bayan Sunnah (Flutter Hadith reader)

## Environment
- Flutter 3.47.9 / Dart 3.13.7 installed at `$HOME/sdk/flutter/bin` (not on PATH by default).
- **No Android SDK, no Java, no clang/cmake/ninja.** `flutter build apk` and
  `flutter build bundle` both fail on "Android SDK could not be found".
  To verify a full AOT compile, temporarily run `flutter create --platforms web .`,
  `flutter build web --release`, then `rm -rf web build`.
- Package name `org.bayan_islamic.sunnah` is set in `android/app/build.gradle.kts`
  (namespace + applicationId), the Kotlin package dir, and the iOS
  PRODUCT_BUNDLE_IDENTIFIER.

## Database
- `assets/sunnah.db` (~5.4 MB) is generated by `tools/build_db.py`; sources are
  cached in `tools/cache/` (gitignored). Final corpus: 5 books, 70 chapters,
  1,897 hadiths. Grades: 1,479 sahih / 50 hasan / 103 da'if / 265 NULL.
- Book ids: 1 Bukhari(260), 2 Muslim(400), 3 Nawawi 40(42), 4 Riyad as-Salihin(400),
  5 Mishkat al-Masabih(795, chapter ids offset at 500+).
- `hadiths.matn_search` holds the Arabic-normalised matn; search queries it, so
  runtime text processing is unnecessary.
- The bundled DB has `PRAGMA user_version = 0`. sqflite's `OpenDatabaseOptions.version`
  makes it try to *write* `PRAGMA user_version`, which fails on a read-only
  connection ("attempt to write a readonly database"). `DatabaseHelper` therefore
  passes `version: readOnly ? null : ...`.
- Tests open the real asset DB via `sqflite_common_ffi` + `DatabaseHelper(databaseFactory:, databasePath:)`
  — see `test/helpers/db_test_utils.dart`. Do NOT mock the database.

## Arabic normalisation
- The Dart normaliser (`lib/core/utils/arabic_normalizer.dart`) must stay
  byte-identical to Python's `normalize_arabic()` in `tools/build_db.py`:
  strip diacritics + tatweel, fold alif variants → ا, ة → ه, ى → ي, collapse
  whitespace. **No NFC** — NFC was verified to be a no-op on this corpus, and
  omitting it guarantees Python/Dart parity.
- `normalizeWithOffsets()` returns the folded string plus source offsets, used to
  highlight a normalised query inside still-diacritised display text.

## Testing notes
- 81 tests. Widget tests must locate the Arabic matn via a `RichText` predicate —
  it is not rendered as a `Text` widget.
- For tests that hit the real SQLite isolate, `pumpAndSettle()` alone hangs on the
  loading spinner; wrap a real delay in `tester.runAsync(...)` first.

## Web support (for preview screenshots)
- `sqflite` has **no web implementation** — the app compiles for web but throws at
  runtime ("Error" with no message) the moment the DB opens. Fixed by adding
  `lib/core/database/platform/` with a conditional export
  (`dart.library.js_interop`): `database_bootstrap_io.dart` (plugin factory +
  asset copy) vs `database_bootstrap_web.dart` (uses `sqflite_common_ffi_web`'s
  `databaseFactoryFfiWeb`, seeds the asset into the wasm VFS via
  `factory.writeDatabaseBytes`). `DatabaseHelper` no longer imports `dart:io`.
- Web needs the two binary assets in `web/`: `sqflite_sw.js` and `sqlite3.wasm`.
  Regenerate with `dart run sqflite_common_ffi_web:setup` (network required).
  Both are committed so `flutter build web` works offline.
- Screenshots (committed under `screenshots/`) were captured with Playwright +
  the system Chromium (`/usr/bin/chromium`, `--no-sandbox`) at 412x915 @2x
  against `python3 -m http.server 8080` serving `build/web`.
- Flutter web renders to canvas, so there is no DOM text. To drive/verify the UI:
  click the `flt-semantics-placeholder` via dispatched PointerEvents to switch on
  the semantics tree, then read `flt-semantics` nodes (they expose innerText +
  role). **Mouse-wheel scrolling is flaky**; dispatch a `WheelEvent` on
  `flt-glass-pane` instead (repeat with ~120ms waits). Grade badges were verified
  by sampling badge colours from the PNG (sahih #059669, hasan #d97706, daif
  #dc2626) rather than by semantics.
